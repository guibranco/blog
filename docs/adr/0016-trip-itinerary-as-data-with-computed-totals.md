# A Trip's Itinerary is a data file rendered by two includes, and every total on the page is computed from it

Travel posts carried their day-by-day plan as a four-column `compare-table` — day, date, a cell of activities joined by "·", and a hand-typed cost per day. It read as a spreadsheet, it was one of the tables that had to scroll sideways on a phone, and its cost column was written by hand next to a financial summary that was also written by hand: on the pilot post the timeline said "≈ € 371" for a day whose itemized charges, all quoted in the same post, add up to € 389,96. Nothing in the build could notice.

**The plan lives in `_data/trips/<slug>.yml`; the Post names it with `trip: <slug>`.** One entry per day with `date`, an optional `title` and its `activities` in order; an activity has a `type` (a key of `_data/activity_types.yml`, which maps it to a Font Awesome icon and a label per Post language), a `title`, and optionally `time`/`end`, `note`, `cost`, `split` (how many people the charge was divided by), `currency` (when it is not the Trip's) and `approx`. Costs paid outside the day-by-day flow — a flight bought months earlier, prepaid lodging, a city-transport total the statement does not break down by day — go under `extras`, so they count toward the Trip without being pinned to a day they did not belong to. The file is the Itinerary term in `CONTEXT.md`; it holds only figures the post states, and a day's title or an activity's type is editorial, not a fact.

**Two includes read the same file, and no total is typed anywhere.** `_includes/timeline.html` renders the days as a vertical timeline and sums each day's costs into a debited total and, when any charge carries a `split`, "my share"; `_includes/trip-summary.html` renders the financial summary — by day, the extras, by category with each category's share, the Trip total and my share — from the same rows. Both are plain Liquid over the data: `plus`, `times: 1.0 | divided_by`, `round: 2`, and the `money`/`percent` filters of `_plugins/money.rb` (which gained a fixed-decimals argument for columns). Amounts in another currency are shown where they happened and summed per currency at the end, but never mixed into the Trip's totals — converting them would be a number the post never stated. The alternative, a Ruby plugin computing the totals into `page.data`, was rejected: the arithmetic is a few dozen lines of Liquid, and keeping it in the includes means a trip file can be checked by rendering it, with nothing hidden in a generator.

**The timeline is a list first and a timeline second; print gets a table.** The markup is an `<ol>` of days, each with an `<h4>` and a `<ul>` of activities whose text reads "type: time title cost" — so with the stylesheet gone it is still a readable list, and toc.js (which collects `h2`/`h3`) does not pick the day headings up. The CSS draws the rail and the dots with pseudo-elements, lets a row wrap under 480px so the cost drops beneath the title instead of forcing horizontal scroll, and uses only the site's tokens, so the dark theme follows. A `<table class="timeline-table" hidden>` with the same rows and the same computed totals follows the list; `@media print` hides the list and shows the table, and `table-scroll.js` now skips hidden tables so the print view does not leave an empty scroll wrapper on screen. Both includes emit no blank line, for the same kramdown reason as the Calculators (ADR-0015).

**The pilot is the London post, because it is the one whose figures reconcile.** Every charge in it is itemized in the prose and in the statement table, the day-level sums plus the unallocated charges add up to the statement total (€ 696,45), and the five charges split three ways reproduce the "my share" figure (€ 534,87) exactly — so the data file could be written without estimating anything. The post keeps its per-merchant statement table (a different view: by charge, with the pound approximation), and gains the computed by-day and by-category tables above it. Malta and Amsterdam quote only per-day approximations in their tables; converting them means going back to their statements, which is the author's work, not a data migration.

## Consequences

- A day total on the page can differ from what the post's prose said before: the pilot's second day now shows € 389,96 where the old table said "≈ € 371", because the computed figure is the sum of the charges the post itself lists. The prose that discussed the estimate was left as it was; it is about the estimate.
- The activity rows are Liquid output of an include, so `reading_time.rb` no longer counts the itinerary's words toward the Post's reading time (ADR-0013 accepts this for includes). On the pilot the rounded estimate did not move (18 minutes before and after); a longer Itinerary could cost a minute.
- The map still reads `location`/`locations` from the front matter (post-map.html, schema.html, travels.html share that merge). A day may carry a `location` in the data file so the same source can feed the map later, but wiring it up touches all three templates and is left for a follow-up rather than done half-way here.
- `audit_blog.py` does not validate `_data/trips/`: an activity type outside `activity_types.yml` silently falls back to `other`, and a `trip` slug with no file renders a visible warning callout instead of failing the build.
- Weekday abbreviations and the day-date format are new keys in `_data/i18n.yml` (`weekday_short`, `timeline_date_format`), because `localized_date` only knows month names.
- See [`CONTEXT.md`](../../CONTEXT.md)'s new **Itinerary** term.
